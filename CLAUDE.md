# CLAUDE.md — yuraz_brand / yurazlab.ru

## Контекст репозитория

Публичное портфолио и профессиональное позиционирование. Репо просматривают работодатели, CTO, технические специалисты, клиенты, партнёры. Всё должно выглядеть как production-grade продукт: код, архитектура, нейминг, README, коммиты, UI.

## Стандарты кода

- Современные best practices — никаких beginner-style решений без необходимости
- Никаких грязных хаков, если есть нормальное архитектурное решение
- Консистентность по всему проекту — стиль, нейминг, структура
- При анализе: прямо указывать слабые места, предупреждать о проблемах масштабирования, замечать технический долг

## Стек

- **Next.js 16** + TypeScript + Tailwind CSS
- **Компоненты:** `landing/components/` — каждая секция отдельный `.tsx`
- **Стили:** только Tailwind-классы, никаких inline-style и сторонних CSS-библиотек
- **Иконки:** только `lucide-react` (уже в зависимостях)
- **Анимации:** без Framer Motion, кроме случаев когда явно просят

## Правила работы

### Перед созданием нового компонента
Одним абзацем: что делает, где живёт, как вписывается в структуру. Потом код.

### Новые секции лендинга
- Создавать как отдельный `.tsx` в `landing/components/`
- Импортировать в `landing/app/page.tsx` в нужном месте
- Имя файла — PascalCase, английский

### Адаптивность
Mobile-first: базовые классы (мобиль), потом `md:` / `lg:`.

### Текст и копирайт
- Простой, живой, без канцелярита
- Обращение на «вы»
- Заголовки конкретные: «Как я работаю», а не «Наш процесс»

### README и документация
- Проект выглядит как серьёзный продукт, не учебная работа
- Акцент на ценности, архитектуре, качестве реализации — повышает доверие

### Кейс-документы (`cases/`)
- Каждый кейс — отдельный `.md`
- Структура: что сделано → стек → результат → ссылки
- Обновлять при смене статуса продукта (Тестирование → Запущен)
